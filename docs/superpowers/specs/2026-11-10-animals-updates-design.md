# Red panda, otter and automatic updates

User requested more animals, specifically a red panda and an otter, different interactions, an otter that also swims, and the same generated movement/transition-image process used for the fox. They also requested automatic delivery of GitHub updates.

Use generated transparent 4x4 base and transition atlases for each species, plus an otter special atlas for entering a swim, paddling, leaving a swim and back-floating. Preserve the existing 80px click target, baseline alignment, hover pause, monitor bounds, sleep/wake and reduced motion. Store a validated species preference defaulting to fox for old profiles. Per the user's follow-up, Animal and Appearance are separate selectors. Every animal supports Natural, Arctic and Midnight; switching animals preserves the selected color. Tighten compact row spacing to keep the same settings window. Give the new animals distinct greeting/phrase pools and playful gestures; let the otter randomly select a slow swim for some trips.

Automatic updates use electron-updater 6 with the existing NSIS/electron-builder 26 stack and the public marcusdiccox/research-buddy GitHub Releases feed. Fetch stable versioned releases, never arbitrary commits, prereleases or downgrades. Installed Windows builds check after startup and every six hours, download quietly and install on ordinary user quit. Skip install during Windows session end. Development, unpacked and isolated-test apps never auto-download/install. A small settings control exposes status and manual checking. Keep a downloaded-ready state through subsequent checks/errors.

Build one stable installer name with latest.yml and blockmap assets. Publish those together for each release; app-update.yml pins the repository. Current 0.8 installs require one manual installation of the updater-enabled release. No GitHub token is needed on users' computers. Keep existing unsigned-Windows status visible in release notes. Validate state behavior, settings migration, swimming transitions/hover/bounds/reduced-motion, all sprite rows and UI persistence. Verify real GitHub metadata/download in an isolated updater probe before claiming end-to-end updates; do not install into the user's running app during a probe.

References: [electron-builder 26 auto-update](https://www.electron.build/v26/docs/features/auto-update/), [Electron Windows session-end events](https://www.electronjs.org/docs/latest/api/browser-window/#event-query-session-end-windows).
