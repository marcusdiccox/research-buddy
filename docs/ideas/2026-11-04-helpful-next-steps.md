# Possible next additions for Pip

Update November 9: natural dates, repeating reminders and quiet focus shipped in 0.7. Daily verified local backups with seven-snapshot retention are now implemented in source; a restore screen remains a proposal. The original research below records the earlier planning context.

Researched November 4, 2026. These are proposals only; none is implemented by the calendar/library update. Ranking reflects my judgment about this small local desktop companion, not a claim that a feature improves everyone's productivity.

1. **Natural-language dates.** Type “tomorrow at 3pm” or “next Friday” and let Pip preview the exact local date before saving. This would reduce fiddling while preserving the new calendar as a fallback. Todoist's official Quick Add documentation demonstrates these phrases; Pip would need its own small local parser and explicit ambiguity handling. Effort: medium. [Todoist Quick Add](https://developer.todoist.com/api/v1/).
2. **Automatic local backups and restore.** Keep a few dated notebook snapshots and provide a tested Restore action. This is my strongest reliability recommendation because Pip currently stores notes locally in SQLite and manual exports are not a complete restore flow. Add integrity checks and a preview before restoring; no cloud account is needed. Effort: medium. Basis: this repository's current storage/export behavior, not an external product claim.
3. **Recurring reminders.** “Every Monday” or monthly tasks could create a next occurrence after completion, applying Pip's existing five warning checkpoints to each event. Todoist supports recurring dates and explicitly distinguishes fixed schedules from schedules based on completion time; Pip would need to make that distinction clear, including daylight-saving behavior and Google event updates. Effort: medium to large. [Recurring dates](https://www.todoist.com/help/todoist/features/introduction-to-recurring-dates-YUYVJJAV).
4. **A short focus session.** Ask Pip to settle beside a tiny timer and pause casual chatter during a work interval, then stretch at the end. Microsoft's Windows Focus pairs a timer with reduced notification distractions; that is useful inspiration rather than a requirement to change Windows settings. Before implementing this, decide whether urgent reminder speech should still interrupt. Effort: small to medium for a local timer; deeper OS integration is separate. [Windows Focus](https://support.microsoft.com/en-us/windows/experience/focus-stay-on-task-without-distractions-in-windows).

The requested Saved search, grouping, recoverable deletion and calendar-picker improvements are being built separately; they are not counted as future ideas. More automatic AI/cloud features are lower priority until the local notebook and recovery story are solid.

Design references used for the requested UI: [Microsoft To Do sorting/search](https://support.microsoft.com/en-us/todo/sort-and-search-in-lists), [list groups](https://support.microsoft.com/en-us/todo/organize-your-lists), and [W3C date-picker keyboard pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/). These inform the design; they do not imply a completed assistive-technology audit.
